# Paper Trading & Simulation Protocol

This document outlines the paper trading protocol, safety lock controls, and order execution workflow for the **Multi-Modal Quant AI Platform**.

---

## 1. Safety Lock Default

By default, the platform enforces `TRADING_ENABLED=False`.
Real-money brokerage execution is **completely disabled**.

Paper trading mode can be explicitly enabled for simulated execution in local or paper environments:
```python
from src.realtime.risk.pretrade_risk import PreTradeRiskChecker
risk_checker = PreTradeRiskChecker(trading_enabled=True) # Paper mode only
```

---

## 2. Order Lifecycle State Machine

Every order transitions through the following mandatory lifecycle states:

```text
CREATED ──> VALIDATING ──> APPROVED ──> SUBMITTED ──> FILLED
   │           │
   └──> REJECTED <──┘ (Risk breach / Insufficient cash)
```

1. **`CREATED`**: Order generated by signal engine.
2. **`VALIDATING`**: Evaluated by `PreTradeRiskChecker`.
3. **`APPROVED`**: Passed pre-trade risk controls.
4. **`SUBMITTED`**: Sent to `PaperExecutionEngine`.
5. **`FILLED`**: Executed with simulated slippage and 10 bps transaction fees.
6. **`REJECTED`**: Order blocked due to risk limits, insufficient cash, or safety lock.
